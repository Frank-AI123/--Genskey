# 财务管理工作台

## v2

- 单文件 HTML 演示：运行 `node build.mjs`，直接用浏览器打开 `dist/index.html`。可离线查看 BI、三张报表、ERP 收入与应收明细、预算和技能样例。页面中的数据为虚构数据。
- 完整工作台：按下方步骤运行 Node.js 服务；登录、财务数据读写、AI 和企业微信功能由服务提供。GitHub Pages 只托管只读演示。
- 发布包不包含本机数据、账号、日志、ERP 工作簿和企业微信配置。公开版配有通用的空白月报模板。

## 启动完整工作台

需要 Node.js 24。解压后在本目录打开 PowerShell。

```powershell
node local.mjs account admin@example.com
node local.mjs
```

把示例邮箱换成你的邮箱。第一条命令用于首次创建管理员，终端只显示一次生成的密码。已有管理员的情况下可以直接启动。打开 http://127.0.0.1:8788 并使用该账户登录。本机版只监听回环地址。

### 注册与密码管理

- **邀请注册：** 管理员在「人员权限」填写同事的登录邮箱、选择角色并保存，然后进入「生成邀请码或重置码」。选择「邀请注册」并把生成的邀请码私下交给同事。同事在登录页选择「注册账号」，填写同一邮箱、邀请码和自己设置的密码。邀请码 24 小时有效，仅可使用一次。
- **修改密码：** 登录后点击右上角「修改密码」，输入当前密码和新密码。成功后所有会话会失效，需要重新登录。
- **忘记密码：** 在登录页点击「忘记密码？」，使用管理员生成的重置码设置新密码。重置码 30 分钟有效，仅可使用一次。本机版由管理员转交验证码。若管理员自己忘记密码，可在网站目录运行 `node local.mjs account 管理员邮箱`，终端会给出新密码，旧会话和验证码会失效。

在「Excel 导入」中下载对应 CSV 模板，用 Excel 填写后保存为 XLSX 或 UTF-8 CSV，再上传并确认预览。应收和月度报表各用一份模板。同编号或同月份的导入记录会替换旧记录，包括已收金额。未导入数据时看板从空库开始。

数据保存在当前目录的 finance.sqlite。关停服务后，可复制该文件进行备份。

## 部门预算管理

1. **设置人员和部门：** 管理员在「人员权限」添加或编辑同事，选择「预算填报员」并填写所属部门。相同部门名称的成员共用一份年度预算，部门名称请统一使用。新增成员按上述邀请注册流程开通账号。预算填报员只看到预算模块和本部门数据；已有财务或管理员账号如需填报本部门，也可在保留原角色的同时设置部门。
2. **在线填报：** 部门同事进入「预算管理」，选择预算年度，按科目和月份填写人民币金额及说明。可以先保存草稿；确认后点击「提交审核」。提交后暂时锁定，财务退回后可按意见修改并重新提交。
3. **财务审核：** 财务或管理员在「预算管理」查看各部门的填报状态、待审金额和已通过金额。打开待审预算后可以通过或填写退回原因。预算详情会保留提交和审核记录。

预算、部门权限和账号同存于 `finance.sqlite`（或 `FINANCE_DB` 指定的文件）。即使应收和月报使用 MySQL，备份时仍须保留这个 SQLite 文件。应用会自动建表。

### 在公司内网共用

默认启动只在本机可访问。各部门需要在自己的电脑填报时，由内部 IT 在工作台所在主机上将公司内网 HTTPS 域名反向代理到 `http://127.0.0.1:8788`，保留原始 `Host` 请求头。DNS 和证书由公司内网环境提供。启动工作台前配置与浏览器访问地址完全一致的 HTTPS 源地址：

```powershell
$env:FINANCE_PUBLIC_ORIGIN = 'https://finance.example.com'
node local.mjs
```

将示例域名替换为公司的实际域名。工作台进程继续监听回环地址；同事通过内网 HTTPS 域名登录。若当前使用 MySQL，启动时继续保留原有的 `FINANCE_STORAGE` 等配置。

## 技能中心

打开左侧「技能中心」，可以按名称、用途或维护人搜索，也可以按分类筛选。进入技能详情查看版本、维护人和使用说明，再打开使用链接或下载 `SKILL.md`。

- **发布与维护：** 财务人员可点击「发布技能」，填写名称、分类、版本、简介和操作步骤，并提供 HTTPS 使用链接或上传、粘贴 `SKILL.md`（至少提供一项）。发布后，所有有工作台权限的同事均可使用。财务人员维护自己发布的条目，管理员可维护全部条目。
- **下架与恢复：** 在技能详情页可下架技能；要恢复发布，从目录切换到「已下架」，再打开详情重新发布。
- **使用方式：** 工作台负责共享说明、链接和 Markdown 文件。技能在所链接的工具或支持该技能的客户端中使用。若还需要脚本、资源或安装包，请将完整包放在同事有权访问的内部地址并填写链接。

本机版的技能目录与账号一同保存在 `finance.sqlite`（或 `FINANCE_DB` 指定的文件），即使业务数据使用 MySQL 也是如此。更新代码后重启工作台服务，数据库会自动创建技能表。

## AI 模型与 BI 智能指标

打开「AI 模型」可查看模型服务商、实际模型标识和平台默认方案，也可选择自己的模型。偏好按账号保存在当前浏览器。首次启动只有「本地规则」，可直接生成常用指标。在「BI 看板 → 智能指标」输入需求，或点击「语音输入」、说出需求并核对转写文字，再点击「生成指标」。例如：

- 「看 10 月营业收入和毛利率」：显示指标卡；未指定年份时使用看板所选年份。
- 「本年每月 ERP 收入趋势」：按当前自然年展示各月数据，缺失月份以短横线标记。
- 「逾期客户前 5 名」：按 ERP 快照中订单核实的 181 天及以上逾期金额排序。

可用口径包括 ERP 不含税收入、报表收入、成本、毛利、毛利率、营业利润、经营现金流，以及应收余额、逾期、回款和 ERP 应收快照。应收台账按开单月筛选，逾期与回款状态使用当前台账；ERP 应收快照以自身截止日为准。累计报表不会被当成单月值画进趋势。自定义公式、客户或部门筛选、同比和环比不在当前生成范围内。生成结果是提交时的查询结果，可再次提交更新。

中文语音使用浏览器的语音识别能力，要求浏览器支持该功能，允许麦克风权限，并通过 HTTPS 或本机回环地址访问；识别可能使用浏览器的在线服务。语音不可用时仍可输入文字。

### 启用可选大模型

在启动本机服务的 PowerShell 里配置 `FINANCE_BI_MODELS`，可启用多个提供 Chat Completions 兼容接口的模型。例如，已在本机 Ollama 安装下列模型时：

```powershell
$env:FINANCE_BI_MODELS = '[{"id":"qwen","name":"本机通义千问","provider":"Ollama","model":"qwen2.5:7b","url":"http://127.0.0.1:11434/v1/chat/completions"}]'
$env:FINANCE_BI_DEFAULT_MODEL = 'local'
node local.mjs
```

把 `model` 改为服务端已启用的实际模型标识，`url` 填完整的 Chat Completions 接口地址。云端或内网接口使用 HTTPS；仅本机回环地址可使用 HTTP。需要密钥时，在配置对象中加入 `"keyEnv":"FINANCE_BI_KEY_MY_PROVIDER"`，从服务端密钥配置提供相应环境变量；浏览器不会收到密钥或接口地址。默认项可改成已配置的 `id`。配置修改后重启工作台。

用户选择外部模型并提交时，工作台会发送需求文字、所选月份、当前月份和指标目录。财务记录不交给模型，查询和计算均在工作台内完成。使用外部模型时，请避免在需求文字里输入敏感信息。

## 公司合并报表与收入管理

进入「Excel 导入 → 公司合并财务报表」，选择公司原格式的 XLSX 文件，核对月份和关键指标后确认导入。工作簿应包含合并资产负债表、合并利润表和合并现金流量表。请在 Excel 中重算并保存，系统读取已保存的单元格数值。

系统按合并利润表的报表日期导入当年截至该月的实际月份。同月份记录会更新。合并资产负债表的期末和期初数据只挂在该报表期，原表本年累计列按原值显示。收入管理可按月查看营业收入、成本、毛利、环比和同比。缺少可比月份时以短横线显示。

## 切换到本机 MySQL

先在 Windows 服务中启动已安装的 MySQL 服务。从网站目录打开 PowerShell，用有建库权限的账号登录。密码在 MySQL 提示符中输入。

```powershell
mysql --host=127.0.0.1 --user=root --password
```

在 MySQL 客户端执行 `source mysql-setup.sql`，然后执行 `exit`。首次运行会显示网站专用账号的随机密码。用下列命令将它保存为当前 Windows 用户的 MySQL 登录配置，按提示输入刚生成的密码。

```powershell
mysql_config_editor set --login-path=finance-desk --host=127.0.0.1 --user=finance_desk_app --password
node local.mjs mysql-check
```

关闭正在运行的旧版网站。如果已有 SQLite 业务数据，运行 `node local.mjs mysql-migrate`。已有的 MySQL 同编号记录会保留，旧 SQLite 数据也保留。然后在同一个 PowerShell 窗口运行：

```powershell
$env:FINANCE_STORAGE = 'mysql'
node local.mjs
```

应收、回款余额和月报从本机 MySQL 读写，网站账号、角色和登录会话保存在原 SQLite 文件。以 MySQL 模式启动时，连接或表检查失败会终止启动。

## ERP 导入接口

ERP API 或导出转换程序可生成 UTF-8 JSON 文件，再调用 `node local.mjs erp-import 文件.json`。每批 1 至 500 行。金额使用整数分，日期使用 YYYY-MM-DD。

```json
{"type":"ar","rows":[{"id":"AR-001","customer":"示例客户","issued":"2026-11-01","due":"2026-12-01","amount":1200000,"paid":300000}]}
```

```json
{"type":"report","rows":[{"id":"2026-11","revenue":10000000,"cost":6000000,"expense":2000000,"cash":1600000}]}
```

相同编号或月份会整行更新，包括已收金额。若 ERP 快照里的已收金额落后于网站登记的回款，先核对并合并后再导入。打开的 BI 看板和应收页每 15 秒查询一次，数据提交后下一次查询即显示。ERP 下载频率由后续的 ERP 接入确定。

## ERP 收入和应收核对快照（本机版）

`finance-erp.sqlite` 是可重建的本机只读查询库，SQLite 和 MySQL 运行模式都可读取它。原有账户、财务报表和应收台账仍由原数据库管理。更新快照前先在新文件里处理和核对；确认后备份旧快照，在同目录替换 `finance-erp.sqlite`。可用 `FINANCE_ERP_DB` 指向其他快照做测试。快照含客户财务数据，应和原财务数据库一起私下备份。

### 发送超 180 天逾期明细到企业微信

财务人员及管理员可在「应收账款」点击「发送超 180 天逾期明细到企业微信」，勾选客户并核对已选金额，选择接收群后点击「确认发送」。消息和跟进记录均以本次勾选的客户为准。金额按 ERP 订单到期日核实，展示尚未收回的正余额。明细较长时发送为文本附件。

发送成功后可点击「查看跟进」，也可在「应收账款 → 推送记录与跟进」打开历史批次。选择客户，填写跟进结果并保存。系统按北京时间显示反馈时间，保留反馈人和每次提交的结果。清单保留推送时的客户和金额，可筛选待反馈和已反馈的客户。推送记录和反馈保存在工作台 SQLite 数据库。

平台预留了「机器人测试群」。在企业微信该群的群设置中取得群机器人 Webhook 地址后，在服务器工作目录创建 `finance-wecom.local.json`，将下例中的地址替换成该群的实际 Webhook。其他群可以在数组中增加不同的 `id`、群名称和对应的 Webhook。平台会在预览和发送时重新读取配置。

```json
[
  {
    "id": "robot-test",
    "name": "机器人测试群",
    "webhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=00000000-0000-0000-0000-000000000000"
  }
]
```

可用 `FINANCE_WECOM_GROUPS_FILE` 指定服务器上的其他配置文件。Webhook 持有者可以向对应群发送消息。配置文件应限制为管理员和服务账号可读，默认文件名已加入 Git 忽略规则。

导入脚本需要 Python 3、`lxml` 和 `openpyxl`。如果回款工作表没有填写「账号名称」，可在脚本同目录创建 `finance-erp-payment-orgs.local.json`，格式为 `{"工作表名称":"收款主体名称"}`。示例以 2026-10-31 为截止日；此前未结的期初单据不计入测算。

```powershell
python import-erp.py "$env:USERPROFILE\Desktop" erp-review.sqlite
python import-erp.py "$env:USERPROFILE\Desktop" erp-inputs.sqlite --aux-only
python reconcile-erp.py erp-review.sqlite erp-inputs.sqlite --cutoff 2026-10-31
```

- BI 按业务日期汇总本位币不含税金额，保留负数及收入表中的总账补充行。缺销售订单号为「其他」。含税原字段确实缺失时，按同一行人民币明细价税合计或本位币不含税金额加税额补足；仍缺的行显示为空，月度已知合计标为「部分」。
- 期末账面余额按客户名称汇总，直接来自应收余额表。订单测算只以已审核的财务应收含税金额为应收基础，同客户、收款主体和同订单核对冲销，暂估不作为应收重复计入。订单金额展示 ERP 收入明细含税合计，单独列示匹配的实际开票和已分配回款。
- 指定订单的回款优先分配给同客户和收款主体的订单。备注逐条列出订单和金额时，按注明金额核销。同一流水下的拆分分录各自核销，业务字段相同的重复记录只计一次。无订单号时，回款表 D 列「回款月份／回款对应月份」能确定一个月份的，在同客户、同收款主体的当月应收中按 ERP 业务日期从早到晚分配。只写月份的，按收款日向前推最近一次同名月份。既无指定订单也无指定月份时，按实际收款月份，在同客户、同收款主体的当月订单内先进先出。超过当月可核销余额的金额留待核对。已注明多个归属月份但无分摊金额的记录，以及多订单无明确分摊、跨期线索、承兑及冲账等问题留待核对。开票按客户、签约主体、订单号或 ERP 发票号匹配。合并发票须能用 ERP 明细核对整张金额才分配，退票状态按源表留待核对。
- 应收到期日＝ERP 业务日期＋客户信用期（日），截止日当天计为未逾期。客户汇总的前三档（未逾期、1–90 天、91–180 天）按订单账龄测算。181 天及以上倒算值＝客户账面期末余额减去前三档，可能包含期初应收、缺账期和核销差异。缺客户账面余额时，倒算值显示为空。前三档合计超过账面余额时，保留倒算的负值并标记待核对。订单明细页另显示按到期日可核实的 181 天及以上金额。
